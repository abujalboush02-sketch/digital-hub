OmniNode API reference

Use the OmniNode API to send events into OmniNode, manage endpoints and mappings, and read delivery logs. Everything here can also be done from the dashboard; the API is for developers who want to automate it.

Base URL
https://api.example.com

All requests and responses use JSON. Field names in responses are camelCase. Times are UTC in ISO 8601.

Quick start

The fastest path from zero to a delivered event. Each step links to its full reference below.

  1. Create a source endpoint and copy its inboundPath.
  2. Create a destination endpoint with the URL that should receive the data.
  3. If the destination needs an API key or token, add a credential for it.
  4. Create a connection from the source to the destination.
  5. Save the mapping rules for that connection.
  6. Point your app at the source's secret URL and send a test event. You get 202 Accepted.
  7. Check the result in events. Processed means it was delivered.

Authentication

Authenticate API calls with your workspace API key in the X-Api-Key header. Your key is shown once when you sign up and whenever you regenerate it (Settings → API key). OmniNode stores only a one-way hash, so we can't show it again.

Headers
X-Api-Key: um_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
Content-Type: application/json

Three ways to authenticate incoming webhooks

MethodWhen to use it
Secret URL (recommended)For apps that can't add headers, like Shopify. The URL itself is the secret. No key needed.
X-Api-KeyFor your own code or tools that let you set headers.
?key=Last resort for senders that can only take a URL. The key may appear in logs, so prefer a secret URL.
Regenerating your API key stops the old key immediately. Secret URLs are separate and keep working until you rotate them.

Responses & errors

OmniNode uses standard HTTP status codes. Errors return a JSON body with an error message.

CodeMeaning
200 / 204Success. 204 has no body (deletes).
202Webhook accepted and queued. Delivery happens in the background.
400Invalid request: missing fields, bad JSON or an invalid value. Read error.
401Missing or invalid API key, or an invalid webhook signature.
402The account isn't active: trial ended, payment overdue, suspended, or paused by an agency.
403Authenticated, but not allowed to access this resource.
404The resource doesn't exist or belongs to another workspace.
409Conflict, e.g. the source is already connected to another destination.
429Monthly task (or AI task) limit reached, including the 10% grace.
402 / 429 body
{
  "error": "Monthly task quota exceeded. Please upgrade your plan.",
  "billingStatus": "Active",
  "tasksUsedThisMonth": 2750,
  "monthlyTaskQuota": 2500,
  "aiTasksUsedThisMonth": 0,
  "aiTasksQuota": 0
}

Webhooks

Send events into OmniNode. Every accepted webhook is stored before we respond, then processed in the background. One accepted webhook = one task.

POST/api/Webhooks/s/{webhookSecret}

The secret URL of a source endpoint (its inboundPath). No API key is needed. The body must be JSON, up to 1 MB. If you set a Shopify signing secret on the endpoint, the X-Shopify-Hmac-Sha256 header is verified and unsigned requests get 401.

cURL
curl -X POST "{{API}}/api/Webhooks/s/whs_7Hc2…" \
  -H "Content-Type: application/json" \
  -d '{ "order_id": "1042", "email": "sara@example.com", "total": "45.50" }'
202 Accepted
{ "message": "Webhook queued successfully for processing." }
POST/api/Webhooks/structured/{endpointId}

Same as above, authenticated with your API key instead of a secret URL.

cURL
curl -X POST "{{API}}/api/Webhooks/structured/3f6c1a2e-…" \
  -H "X-Api-Key: um_live_…" \
  -H "Content-Type: application/json" \
  -d '{ "receipt_no": "ORD-1042", "total_cents": 35000 }'

AI message parsing

POST/api/Webhooks/unstructured/{endpointId}?userId={senderId}

Send free-text messages (for example from a WhatsApp or Telegram bot). The AI extracts structured fields, which then flow through your mapping. userId identifies the sender, such as a phone number. Each call uses one task and one AI task.

cURL
curl -X POST "{{API}}/api/Webhooks/unstructured/3f6c1a2e-…?userId=962791234567" \
  -H "X-Api-Key: um_live_…" \
  -H "Content-Type: application/json" \
  -d '{ "text": "بدي ٣ علب كريم، التوصيل على خلدا، رقمي 0791234567" }'
Only messages sent to this endpoint are processed by our AI provider, and only to extract fields. Your data is not used to train models.

Endpoints

An endpoint is either a source (where events come from) or a destination (where they are delivered). Source endpoints get a secret inbound URL automatically.

POST/api/Endpoints
Request
curl -X POST "{{API}}/api/Endpoints" \
  -H "X-Api-Key: um_live_…" -H "Content-Type: application/json" \
  -d '{ "platformName": "Shopify store", "endpointType": "source" }'

curl -X POST "{{API}}/api/Endpoints" \
  -H "X-Api-Key: um_live_…" -H "Content-Type: application/json" \
  -d '{ "platformName": "Courier API", "endpointType": "destination",
        "webhookUrl": "https://courier.example.com/api/shipments" }'
200 OK
{
  "id": "3f6c1a2e-…",
  "platformName": "Shopify store",
  "endpointType": "source",
  "webhookUrl": "",
  "webhookSecret": "whs_7Hc2…",
  "inboundPath": "/api/Webhooks/s/whs_7Hc2…",
  "hasSigningSecret": false
}

endpointType must be source or destination. Destinations need a valid http(s) webhookUrl.

RequestWhat it does
GET /api/EndpointsList your endpoints.
GET /api/Endpoints/{id}Get one endpoint.
POST /api/Endpoints/{id}/rotate-webhook-secretIssue a new secret URL. The old one stops working immediately.
PUT /api/Endpoints/{id}/signing-secretSet {"signingSecret":"…"} to verify Shopify signatures; send null to remove it.
DELETE /api/Endpoints/{id}Delete the endpoint and its connections and events.

Credentials

Store the key or token your destination requires. OmniNode attaches it when delivering to that destination.

POST/api/Credentials
Request
curl -X POST "{{API}}/api/Credentials" \
  -H "X-Api-Key: um_live_…" -H "Content-Type: application/json" \
  -d '{
    "endpointId": "9b1d…",
    "baseUrl": "https://courier.example.com",
    "apiKey": "courier_secret_token",
    "authType": "Bearer"
  }'
GET /api/CredentialsList stored credentials.
DELETE /api/Credentials/{id}Delete a credential.

Connections

A connection links one source to one destination. A new connection starts as MappingRequired and becomes Active once you save its mapping.

POST/api/Connections
Request
curl -X POST "{{API}}/api/Connections" \
  -H "X-Api-Key: um_live_…" -H "Content-Type: application/json" \
  -d '{ "sourceEndpointId": "3f6c1a2e-…", "destinationEndpointId": "9b1d…" }'

Sending the same pair again returns the existing connection. A source that's already connected to a different destination returns 409 with existingConnectionId.

GET /api/ConnectionsList connections with status and rule count.
DELETE /api/Connections/{id}Delete a connection and its mapping.

Mappings & discovery

Rules describe how each source field becomes a destination field. Use dotted paths for nested fields, e.g. customer.email.

POST/api/Mappings/configure
Request
curl -X POST "{{API}}/api/Mappings/configure" \
  -H "X-Api-Key: um_live_…" -H "Content-Type: application/json" \
  -d '{
    "connectionId": "b41d…",
    "rules": [
      { "endpointId": "3f6c1a2e-…", "sourceKey": "customer.email",
        "targetKey": "Email", "type": "string", "math": "", "isRequired": true },
      { "endpointId": "3f6c1a2e-…", "sourceKey": "total",
        "targetKey": "Amount", "type": "number", "math": "", "isRequired": false }
    ],
    "sourceSchema": "{\"customer\":{\"email\":\"\"},\"total\":\"\"}",
    "destinationSchema": "{\"Email\":\"\",\"Amount\":0}"
  }'

endpointId is the source endpoint. type is string, number, boolean or date. math is optional, using the same syntax as the Mapping Studio. The sample schemas are optional; saving them enables suggestions later.

GET /api/Mappings/{connectionId}Load the saved rules and sample schemas.
POST /api/Mappings/suggestSend {"sourceJson":"…","destinationJson":"…"} and get suggested sourceKey → targetKey pairs.
GET /api/Mappings/suggest/{connectionId}Suggestions from the schemas saved on a connection.
POST /api/schemas/discover-customSend {"rawJson":"…"} or {"fieldList":["a","b"]} to register a custom schema from a sample.

Templates

GET/api/Templates

Built-in sample schemas you can start a mapping from. Each item has name, sampleJson and a flat fields list.

Events & retries

Every accepted webhook becomes an event: Pending → Processing → Processed. If delivery fails, OmniNode keeps trying, up to 5 attempts in total, with growing waits between them (about 5, 10, 15 and 20 minutes). After that it becomes Failed_ManualReviewRequired and waits for you to retry it.

GET /api/Events/logsThe 50 most recent events.
GET /api/Events/allThe 200 most recent events.
GET /api/Events/pendingEvents waiting to be delivered.
GET /api/Events/failedEvents that need attention, with failureReason.
POST /api/Events/{id}/retryRe-queue one failed event.
POST /api/Events/retry-failed?endpointId=Re-queue all failed events (optionally for one endpoint). Returns {"requeued": n}.
Event
{
  "id": "e1a2…",
  "endpointId": "3f6c1a2e-…",
  "status": "Failed_ManualReviewRequired",
  "retryCount": 5,
  "maxRetries": 5,
  "failureReason": "Destination returned 401 Unauthorized",
  "receivedAt": "2026-10-28T09:14:03Z",
  "lastAttemptAt": "2026-10-28T10:04:11Z",
  "payload": "{ … }"
}

Retries never use extra tasks.

Account & API key

GET /api/Tenants/{tenantId}Your plan, status, renewal date, usage and quotas.
POST /api/Tenants/{tenantId}/generate-keyCreate a new API key (shown once). The old key stops working immediately.

Limits & quotas

  • Tasks: each accepted webhook counts once against your monthly quota. AI messages also count once against your AI quota.
  • Grace: webhooks are accepted up to 110% of your quota. Above that you get 429 until you upgrade or the month resets.
  • Account status: during a free trial or an active plan everything works. When a trial ends or an account is suspended, webhooks return 402; your setup is kept.
  • Payload size: up to 1 MB per webhook on secret URLs.
  • Agencies: a client's webhooks count against both the client's allocation and the agency's pooled quota.
